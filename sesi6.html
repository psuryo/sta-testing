White-Box Testing: Statement, Branch, Path Coverage

Jika Sesi 5 merancang test case dari sudut pandang spesifikasi, sesi ini membalik sudut pandang: merancang test case dengan melihat langsung struktur kode untuk memastikan seberapa jauh baris, cabang, dan jalur eksekusi program benar-benar diuji.

⏱ 50 menit 🎯 CPMK-2, CPMK-3 📖 3 referensi utama

Tujuan Pembelajaran

Setelah mengikuti sesi ini, mahasiswa mampu:

  • ✓ Menjelaskan prinsip dasar White-Box Testing dan bedanya dengan Black-Box Testing.
  • ✓ Menggambarkan Control Flow Graph (CFG) dari potongan kode sederhana.
  • ✓ Menghitung dan merancang test case untuk mencapai Statement Coverage, Branch Coverage, dan Path Coverage.
  • ✓ Menghitung Cyclomatic Complexity menggunakan dua pendekatan rumus, dan mengaitkannya dengan jumlah minimum test case.
  • ✓ Menjelaskan hubungan hierarki kekuatan antara ketiga jenis coverage tersebut.
6.1

Definisi White-Box Testing

White-Box Testing (disebut juga Structural Testing atau Glass-Box Testing) adalah pendekatan pengujian yang merancang test case berdasarkan struktur internal kode — baris program, percabangan logika, dan jalur eksekusi — bukan berdasarkan spesifikasi semata seperti Black-Box Testing (Sesi 5).

💡 Kontras dengan Black-Box: Black-Box bertanya "apakah output benar untuk input tertentu, menurut spesifikasi?". White-Box bertanya "apakah baris/cabang/jalur kode ini benar-benar dieksekusi minimal satu kali oleh test suite saya?". Karena butuh melihat kode, White-Box Testing umumnya dilakukan oleh developer pada level Unit Testing (ingat kembali Sesi 4).

Ukuran keberhasilan White-Box Testing disebut Code Coverage — persentase elemen kode (baris, cabang, atau jalur) yang telah dieksekusi oleh test suite. Sesi ini membahas tiga level coverage yang paling umum: Statement, Branch, dan Path Coverage.

6.2

Control Flow Graph (CFG)

Sebelum menghitung coverage, kode program perlu digambarkan sebagai Control Flow Graph — diagram yang merepresentasikan setiap kemungkinan jalur eksekusi sebagai node (pernyataan/keputusan) yang dihubungkan oleh edge (alur kontrol).

Contoh Kode: Menentukan Ongkos Kirim Gratis

Kode ini akan dipakai sebagai contoh utama sepanjang sesi ini.

function cekOngkirGratis(berat, isMember):
    gratisOngkir = false

    if (berat >= 5):              // D1
        gratisOngkir = true

    if (isMember):               // D2
        gratisOngkir = true

    return gratisOngkir

Kode ini memiliki dua keputusan independen (D1 dan D2) yang berjalan berurutan, bukan bersarang (nested). Berikut CFG-nya dalam bentuk pohon:

Mulai ↓ D1: berat ≥ 5 ?
YA → gratisOngkir = true
↓  (kedua cabang bertemu di sini) D2: isMember ?
YA → gratisOngkir = true
↓  (kedua cabang bertemu di sini) return gratisOngkir
NodeKeterangan
N1Mulai / inisialisasi gratisOngkir = false
N2Decision D1: berat ≥ 5?
N3gratisOngkir = true (cabang YA dari D1)
N4Decision D2: isMember?
N5gratisOngkir = true (cabang YA dari D2)
N6return gratisOngkir
6.3

Statement Coverage

Statement Coverage mengukur persentase baris/pernyataan kode yang telah dieksekusi minimal satu kali oleh test suite.

Statement Coverage = (Jumlah statement dieksekusi ÷ Total statement) × 100%

Untuk kode cekOngkirGratis di atas, satu test case dengan berat ≥ 5 DAN isMember = true akan melewati N1 → N2 → N3 → N4 → N5 → N6 — seluruh node/statement dilalui dalam satu eksekusi.

Test CaseberatisMemberStatement DilaluiCoverage
TC-016trueN1, N2, N3, N4, N5, N6100%
⚠ Kelemahan penting: hanya dengan satu test case, Statement Coverage 100% sudah tercapai! Namun perhatikan — cabang false dari D1 dan D2 (yaitu skenario berat < 5 atau isMember = false) tidak pernah diuji sama sekali. Inilah sebabnya Statement Coverage dianggap sebagai ukuran paling lemah di antara ketiga jenis coverage.
6.4

Branch Coverage (Decision Coverage)

Branch Coverage mengukur apakah setiap keputusan (decision) telah diuji pada kedua kemungkinan hasil-nya — true dan false — minimal satu kali oleh test suite.

Branch Coverage = (Jumlah cabang dieksekusi ÷ Total cabang) × 100%

Kode kita memiliki 2 decision (D1, D2), masing-masing dengan 2 kemungkinan hasil → total 4 cabang yang perlu diuji: D1-true, D1-false, D2-true, D2-false.

Test CaseberatisMemberD1D2
TC-016trueTRUETRUE
TC-022falseFALSEFALSE
✓ Poin kunci: hanya dengan 2 test case (TC-01 dan TC-02), keempat cabang (D1-true, D1-false, D2-true, D2-false) sudah tercakup semua — sekaligus otomatis mencapai 100% Statement Coverage juga. Branch Coverage secara matematis selalu lebih kuat atau setara dengan Statement Coverage.
6.5

Path Coverage dan Cyclomatic Complexity

Path Coverage mengukur apakah setiap kombinasi jalur eksekusi yang mungkin dari awal hingga akhir program telah diuji — bukan sekadar tiap cabang secara terpisah, melainkan tiap kombinasi cabang.

⚠ Peringatan penting: menguji seluruh kemungkinan kombinasi jalur secara harfiah (disebut all-path coverage) seringkali tidak praktis atau bahkan mustahil — terutama jika ada perulangan (loop), jumlah kombinasi jalur bisa tak terhingga. Karena itu, dalam praktik nyata, "Path Coverage" hampir selalu merujuk pada Basis Path Testing: menguji sejumlah minimum jalur yang secara linear independen, yang jumlahnya ditentukan oleh Cyclomatic Complexity.

Menghitung Cyclomatic Complexity — Dua Rumus

McCabe (1976) mendefinisikan dua cara menghitung yang selalu menghasilkan angka sama untuk graf yang sama:

V(G) = E − N + 2   |   V(G) = Jumlah Decision Point + 1
VariabelNilai pada Contoh Kita
N (jumlah node)6 (N1–N6)
E (jumlah edge)7 (N1→N2, N2→N3, N2→N4, N3→N4, N4→N5, N4→N6, N5→N6)
Rumus 1: V(G) = E − N + 27 − 6 + 2 = 3
Jumlah Decision Point2 (D1 dan D2)
Rumus 2: V(G) = Decision Point + 12 + 1 = 3

*Kedua rumus menghasilkan angka yang sama: V(G) = 3. Artinya, dibutuhkan minimal 3 test case dengan jalur yang berbeda secara linear untuk mencapai basis path coverage.

Menyusun 3 Basis Path

Perhatikan bahwa secara kombinatorial, D1 dan D2 menghasilkan 4 kemungkinan jalur (TT, TF, FT, FF). Namun cyclomatic complexity mengatakan hanya 3 jalur independen yang dibutuhkan — jalur keempat dapat "diturunkan" sebagai kombinasi dari ketiga jalur lainnya, sehingga tidak menambah informasi struktural baru.

Test CaseberatisMemberD1D2Jalur
TC-016trueTTN1-N2-N3-N4-N5-N6
TC-022falseFFN1-N2-N4-N6
TC-036falseTFN1-N2-N3-N4-N6

*Jalur ke-4 (berat < 5, isMember = true → N1-N2-N4-N5-N6) tidak wajib diuji terpisah untuk basis path coverage, karena strukturnya sudah terwakili secara linear oleh kombinasi TC-01, TC-02, dan TC-03. Dalam praktiknya, banyak tim tetap menguji jalur ke-4 ini juga sebagai bagian dari Branch Coverage — sekali lagi menunjukkan bagaimana ketiga jenis coverage saling melengkapi.

6.6

Hierarki Kekuatan Coverage

Dari ketiga contoh di atas, terlihat pola yang konsisten: 1 test case cukup untuk Statement Coverage, 2 test case untuk Branch Coverage, dan 3 test case untuk Path/Basis Coverage. Ini bukan kebetulan — ada hubungan hierarki matematis di antara ketiganya.

Path Coverage
paling kuat & menyeluruh
Branch Coverage
mencakup Statement Coverage
Statement Coverage
paling lemah & paling mudah dicapai
✓ Poin kunci: 100% Path Coverage otomatis memenuhi 100% Branch Coverage, dan 100% Branch Coverage otomatis memenuhi 100% Statement Coverage — namun tidak berlaku sebaliknya. Inilah alasan Statement Coverage saja tidak boleh dijadikan satu-satunya tolok ukur kualitas unit testing.
6.7

Kelebihan dan Keterbatasan White-Box Testing

Kelebihan

  • Menjamin cakupan struktur kode secara terukur (coverage %)
  • Efektif menemukan dead code (kode yang tidak pernah dieksekusi)
  • Menemukan bug logika internal yang tidak terlihat dari spesifikasi
  • Dapat diotomasi dan diintegrasikan ke tools coverage (JaCoCo, Coverage.py, dll.)

Keterbatasan

  • Memerlukan akses dan pemahaman terhadap kode sumber
  • Coverage 100% tidak menjamin tidak ada bug — hanya menjamin baris/cabang dieksekusi, bukan menjamin logika bisnisnya benar
  • Tidak menguji kesesuaian dengan kebutuhan pengguna (perlu dilengkapi Black-Box Testing)
  • Path Coverage penuh bisa sangat mahal/mustahil pada kode dengan banyak loop dan decision

Latihan Kelas: Analisis Kode Diskon

Kerjakan berpasangan selama 10 menit, lalu bahas bersama.

Latihan

Fungsi Penentu Diskon Member

function hitungDiskon(totalBelanja, isMemberPremium):
    diskon = 0

    if (totalBelanja > 500000):
        diskon = 0.10
    else:
        diskon = 0.05

    if (isMemberPremium):
        diskon = diskon + 0.05

    return diskon
  • Gambarkan Control Flow Graph dari kode di atas (identifikasi node dan decision point).
  • Hitung Cyclomatic Complexity menggunakan kedua rumus.
  • Rancang test case minimum untuk mencapai 100% Statement Coverage.
  • Rancang test case minimum untuk mencapai 100% Branch Coverage.
  • Rancang basis path test case sesuai jumlah Cyclomatic Complexity yang dihitung.

Bandingkan hasil kerja Anda dengan pasangan lain — apakah jumlah test case yang dihasilkan sama?

Rangkuman

  • ✓ White-Box Testing merancang test case berdasarkan struktur internal kode, biasanya dilakukan developer pada level Unit Testing.
  • ✓ Control Flow Graph (CFG) merepresentasikan kode sebagai node (pernyataan/keputusan) dan edge (alur kontrol) sebagai dasar penghitungan coverage.
  • ✓ Statement Coverage mengukur baris kode yang dieksekusi — paling mudah dicapai namun paling lemah.
  • ✓ Branch Coverage mengukur kedua hasil (true/false) tiap keputusan — lebih kuat dan otomatis mencakup Statement Coverage.
  • ✓ Path Coverage dalam praktiknya berarti Basis Path Testing, dengan jumlah minimum jalur = Cyclomatic Complexity (V(G) = E − N + 2 = Decision Point + 1).
  • ✓ Ketiga jenis coverage membentuk hierarki kekuatan: Path ⊇ Branch ⊇ Statement, tapi tidak berlaku sebaliknya.

Latihan Pemahaman Mandiri

Klik tiap soal untuk melihat kunci jawaban dan penjelasannya.

1. Sebuah fungsi memiliki 3 decision point independen (tidak bersarang). Berapa Cyclomatic Complexity-nya, dan berapa minimum basis path yang dibutuhkan?
Jawaban: V(G) = Decision Point + 1 = 3 + 1 = 4. Dibutuhkan minimal 4 basis path (test case dengan jalur berbeda secara linear) untuk mencapai path/basis coverage.
2. Mengapa 100% Statement Coverage tidak menjamin tidak ada bug pada kode?
Jawaban: Karena Statement Coverage hanya memastikan setiap baris dieksekusi minimal satu kali — tidak memastikan kedua hasil (true/false) dari setiap keputusan telah diuji. Bug yang hanya muncul pada cabang false suatu decision bisa saja tidak pernah terdeteksi meski Statement Coverage sudah 100%.
3. Apa perbedaan mendasar antara "Path Coverage" secara harfiah (all-path) dengan "Basis Path Testing"?
Jawaban: All-path coverage menuntut pengujian seluruh kemungkinan kombinasi jalur eksekusi, yang jumlahnya bisa sangat besar atau tak terhingga (terutama dengan loop) — sehingga sering tidak praktis. Basis Path Testing hanya menguji jumlah minimum jalur yang secara linear independen sebanyak Cyclomatic Complexity, yang secara struktural sudah cukup mewakili seluruh kombinasi logis tanpa harus menguji semuanya secara harfiah.
4. Jika sebuah test suite sudah mencapai 100% Branch Coverage, apakah otomatis mencapai 100% Statement Coverage juga? Jelaskan.
Jawaban: Ya, otomatis. Karena untuk menguji kedua hasil (true/false) dari suatu keputusan, seluruh pernyataan pada kedua cabang tersebut pasti ikut tereksekusi. Ini sesuai hierarki kekuatan coverage: Branch Coverage selalu lebih kuat atau setara dengan Statement Coverage, tidak pernah lebih lemah.

Tugas Sesi 6

Analisis Coverage & Cyclomatic Complexity

Diberikan potongan kode berikut (fungsi penentu status pengiriman berdasarkan berat paket dan jenis layanan):

function tentukanBiayaKirim(berat, jenisLayanan):
    biaya = 0

    if (jenisLayanan == "reguler"):
        if (berat <= 3):
            biaya = 10000
        else:
            biaya = 10000 + (berat - 3) * 2000
    else:
        if (berat <= 3):
            biaya = 20000
        else:
            biaya = 20000 + (berat - 3) * 3000

    return biaya

Kerjakan dan susun dalam laporan:

(1) Gambarkan Control Flow Graph lengkap dengan penomoran node
(2) Hitung Cyclomatic Complexity menggunakan kedua rumus (V=E−N+2 dan V=Decision Point+1), tunjukkan hasil keduanya sama
(3) Rancang test case minimum untuk 100% Statement Coverage
(4) Rancang test case minimum untuk 100% Branch Coverage
(5) Rancang basis path test case sejumlah Cyclomatic Complexity yang dihitung, lengkap dengan nilai input dan jalur yang dilalui
