Procedural Testing & Object Oriented Testing

Dua sesi sebelumnya membahas alat untuk menulis unit test. Sesi ini membahas cara berpikir merancang test sesuai paradigma kode: prosedural (alur kontrol dan aliran data) dan berorientasi objek (state, pewarisan, polimorfisme). Contoh memakai Python dan PyTest.

⏱ 50 menit 🎯 CPMK-3, CPMK-4 🧩 White-box & OO

Tujuan Pembelajaran

Setelah mengikuti sesi ini, mahasiswa mampu:

  • ✓ Menjelaskan karakteristik pengujian prosedural dan pengujian berorientasi objek.
  • ✓ Menggambar control flow graph dan menghitung cyclomatic complexity.
  • ✓ Menurunkan test case dari basis path, data flow, dan loop testing.
  • ✓ Menguji class berbasis state serta kasus pewarisan dan polimorfisme.
  • ✓ Memilih strategi pengujian yang tepat untuk kode prosedural versus OO.
10.1

Procedural Testing

Procedural testing menguji kode yang tersusun dari fungsi/prosedur dengan alur kontrol (percabangan dan perulangan) serta data yang mengalir antarvariabel. Pendekatannya white-box: test dirancang dari struktur internal kode, bukan hanya dari spesifikasi.

TeknikFokusPertanyaan yang dijawab
Statement / Branch CoverageBaris dan cabangApakah semua baris dan keputusan pernah dijalankan?
Basis Path TestingJalur independenBerapa test minimum agar setiap jalur independen teruji?
Data Flow TestingDefinisi & pemakaian variabelApakah setiap nilai variabel benar-benar dipakai dengan benar?
Loop TestingPerulanganBagaimana perilaku di 0, 1, dan banyak iterasi?
💡Statement dan Branch Coverage sudah dibahas di sesi 6. Sesi ini melanjutkan ke teknik yang lebih sistematis dalam menentukan test mana yang minimal dan cukup.
10.2

Basis Path Testing & Cyclomatic Complexity

Langkah: (1) ubah kode menjadi control flow graph (node = blok statement, edge = aliran kontrol), (2) hitung cyclomatic complexity V(G), (3) tentukan V(G) jalur independen, (4) buat satu test per jalur.

def ongkir(berat, kota, member): if berat <= 0: # keputusan 1 raise ValueError("Berat tidak valid") biaya = berat * 5_000 if kota == "luar": # keputusan 2 biaya += 20_000 if member: # keputusan 3 biaya *= 0.9 return biaya
Rumus V(G)Hasil pada fungsi di atas
Jumlah keputusan + 13 + 1 = 4
Edge − Node + 2Sama, yaitu 4 (dari graph)
Jumlah region pada graph4

Karena V(G) = 4, diperlukan minimal 4 test untuk menutup semua jalur independen:

import pytest from ongkir_mod import ongkir def test_jalur1_berat_tidak_valid(): with pytest.raises(ValueError): ongkir(0, "dalam", False) def test_jalur2_dalam_kota_non_member(): assert ongkir(2, "dalam", False) == 10_000 def test_jalur3_luar_kota_non_member(): assert ongkir(2, "luar", False) == 30_000 def test_jalur4_luar_kota_member(): assert ongkir(2, "luar", True) == pytest.approx(27_000)
✓Kegunaan V(G): selain menentukan jumlah test minimum, V(G) mengukur kerumitan kode. Nilai umumnya dianggap sederhana (1–10), perlu perhatian (11–20), dan berisiko tinggi (>20) sehingga layak di-refactor.
10.3

Data Flow & Loop Testing

Data Flow Testing

Menelusuri siklus hidup variabel: def (diberi nilai), c-use (dipakai dalam perhitungan), p-use (dipakai dalam kondisi). Test dirancang agar setiap pasangan def–use terlewati.

AnomaliContohRisiko
Use tanpa defVariabel dipakai sebelum diberi nilaiError atau nilai tak terduga
Def tanpa usebiaya dihitung tetapi tidak pernah dipakaiKode mati atau logika terlewat
Def dua kali berturutNilai pertama ditimpa tanpa dipakaiKemungkinan salah ketik/logika

Loop Testing

SkenarioUntuk loop dengan batas n
Lewati loop0 iterasi
Iterasi minimum1 iterasi
Iterasi umum2 hingga n−1 iterasi
Batasn−1, n, dan n+1 iterasi
@pytest.mark.parametrize("data, total", [ ([], 0), # 0 iterasi ([5], 5), # 1 iterasi ([1, 2, 3], 6), # banyak iterasi ]) def test_jumlah_loop(data, total): assert jumlah(data) == total
10.4

Object Oriented Testing

Pada kode OO, unit terkecil bukan lagi fungsi, melainkan class: data (atribut) dan perilaku (method) berpadu. Hasil sebuah method sering bergantung pada state objek akibat pemanggilan sebelumnya, sehingga menguji method satu per satu secara terpisah tidak cukup.

Karakteristik OOTantangan pengujian
EncapsulationState internal tersembunyi; verifikasi lewat perilaku publik, bukan mengintip atribut privat
StateUrutan pemanggilan method memengaruhi hasil
InheritanceMethod turunan dapat berperilaku berbeda dalam konteks subclass
PolymorphismSatu pemanggilan, banyak kemungkinan implementasi
CollaborationObjek bergantung pada objek lain (butuh stub/mock)

Level Pengujian pada OO

  • 01
    Method
    Menguji satu method dengan teknik prosedural (basis path, BVA).
  • 02
    Class
    Menguji urutan pemanggilan method dan perubahan state.
  • 03
    Cluster
    Menguji sekelompok class yang saling berkolaborasi (integration test).
10.5

State-based Testing

Contoh class kursi pada sistem reservasi (relevan dengan proyek Kelompok A), dengan state TERSEDIA → DIPESAN → TERJUAL:

class Kursi: def __init__(self): self.status = "TERSEDIA" def pesan(self): if self.status != "TERSEDIA": raise RuntimeError("Kursi tidak tersedia") self.status = "DIPESAN" def bayar(self): if self.status != "DIPESAN": raise RuntimeError("Belum dipesan") self.status = "TERJUAL" def batal(self): if self.status == "DIPESAN": self.status = "TERSEDIA"

Rancang test dari state machine: setiap transisi valid diuji, dan setiap transisi tidak valid harus ditolak.

State awalEventHasil yang diharapkan
TERSEDIApesan()DIPESAN
TERSEDIAbayar()RuntimeError (transisi tidak valid)
DIPESANbayar()TERJUAL
DIPESANbatal()TERSEDIA
DIPESANpesan()RuntimeError (pesan ganda)
TERJUALpesan() / batal()Error / state tetap TERJUAL
@pytest.fixture def kursi_dipesan(): k = Kursi(); k.pesan() return k def test_pesan_mengubah_state(): k = Kursi(); k.pesan() assert k.status == "DIPESAN" def test_bayar_dari_dipesan(kursi_dipesan): kursi_dipesan.bayar() assert kursi_dipesan.status == "TERJUAL" def test_pesan_ganda_ditolak(kursi_dipesan): with pytest.raises(RuntimeError): kursi_dipesan.pesan() def test_bayar_tanpa_pesan_ditolak(): with pytest.raises(RuntimeError): Kursi().bayar() def test_batal_mengembalikan_tersedia(kursi_dipesan): kursi_dipesan.batal() assert kursi_dipesan.status == "TERSEDIA"
⚠Test di atas memeriksa status secara langsung karena atribut itu bagian dari kontrak publik. Jika state benar-benar privat, verifikasi lewat perilaku yang teramati (mis. method tersedia()), jangan lewat atribut internal.
10.6

Inheritance & Polimorfisme

class Pembayaran: def biaya_admin(self, nominal): return 2_500 class KartuKredit(Pembayaran): def biaya_admin(self, nominal): # override return nominal * 0.025 class Gopay(Pembayaran): pass # mewarisi apa adanya
  • ✓ Uji ulang method warisan di subclass. Method yang diwarisi dapat berperilaku berbeda karena state atau method lain yang di-override.
  • ✓ Uji setiap override. Subclass hanya lolos jika perilakunya tetap konsisten dengan kontrak parent (Liskov Substitution Principle).
  • ✓ Gunakan satu rangkaian test untuk semua subclass. Test dijalankan terhadap tiap implementasi dengan parametrize.
  • ✓ Abstract class tidak bisa diinstansiasi. Uji lewat subclass konkret atau test double.
@pytest.mark.parametrize("kelas", [Pembayaran, KartuKredit, Gopay]) def test_kontrak_biaya_admin_tidak_negatif(kelas): assert kelas().biaya_admin(100_000) >= 0 # kontrak umum semua subclass def test_kartu_kredit_menghitung_persen(): assert KartuKredit().biaya_admin(100_000) == 2_500

Untuk kolaborasi antarobjek (mis. Kursi memanggil layanan notifikasi), gunakan mock seperti pada sesi 9 agar class diuji secara terisolasi.

10.7

Perbandingan Procedural vs Object Oriented Testing

AspekProceduralObject Oriented
Unit ujiFungsi/prosedurClass (method + state)
Fokus utamaAlur kontrol & aliran dataState, interaksi, pewarisan
Teknik andalanBasis path, data flow, loopState-based, sequence test, kontrak subclass
Ketergantungan hasilTerutama pada inputInput dan riwayat pemanggilan
Isolasi dependensiJarang dibutuhkanSering memakai mock/stub
💡Keduanya saling melengkapi. Di dalam sebuah class OO, setiap method tetap berisi logika prosedural yang diuji dengan basis path dan BVA; teknik OO menambahkan lapisan untuk state dan hubungan antarclass.

Latihan Kelas: Dua Pendekatan, Satu Sistem

Kerjakan berpasangan selama 15 menit.

Latihan

Kode Promo & Keranjang Belanja

Bagian A (prosedural): fungsi hitung_promo(total, kode, member) memiliki 4 keputusan: total > 0, kode valid, kode kedaluwarsa, dan member.

  • Hitung V(G) dan tuliskan jalur independennya.
  • Buat satu test PyTest per jalur.

Bagian B (OO): class Keranjang dengan state KOSONG → BERISI → CHECKOUT.

  • Gambar state machine dan tabel transisi valid/tidak valid.
  • Tulis minimal 4 test, termasuk 2 transisi tidak valid.

Pada Bagian B, mengapa memanggil checkout() pada keranjang KOSONG harus diuji secara eksplisit?

Rangkuman

  • ✓ Procedural testing bersifat white-box: berfokus pada alur kontrol dan aliran data fungsi.
  • ✓ Cyclomatic complexity V(G) = jumlah keputusan + 1 sekaligus menjadi jumlah test minimum pada basis path testing.
  • ✓ Data flow dan loop testing menangkap bug yang lolos dari coverage biasa.
  • ✓ Pada OO testing, unit adalah class: state, urutan pemanggilan, pewarisan, dan polimorfisme menjadi fokus.
  • ✓ State machine membantu menurunkan test transisi valid maupun tidak valid secara sistematis.

Latihan Pemahaman Mandiri

Klik tiap soal untuk melihat kunci jawaban.

1. Sebuah fungsi memiliki 5 keputusan (if) yang tidak bersarang. Berapa V(G) dan test minimumnya?
Jawaban: V(G) = 5 + 1 = 6, sehingga dibutuhkan minimal 6 test untuk menutup semua jalur independen.
2. Mengapa 100% statement coverage belum tentu menutup semua jalur?
Jawaban: Statement coverage hanya memastikan setiap baris dijalankan. Cabang "tidak" dari sebuah if tanpa else, serta kombinasi antarkeputusan, bisa tidak pernah diuji meski semua baris sudah tersentuh.
3. Mengapa method yang diwarisi tetap perlu diuji ulang pada subclass?
Jawaban: Karena konteksnya berubah: subclass dapat meng-override method yang dipanggil di dalamnya atau menambah state, sehingga perilaku method warisan dapat berbeda dari yang diuji pada parent.
4. Apa yang membedakan pengujian class dari pengujian fungsi biasa?
Jawaban: Hasil method class dapat bergantung pada state hasil pemanggilan sebelumnya, sehingga test harus mencakup urutan pemanggilan dan transisi state, bukan hanya pasangan input–output.

Procedural & OO Test Suite

Pilih satu modul prosedural dan satu class OO dari topik proyek kelompok Anda (boleh disederhanakan). Kerjakan:

(1) Control flow graph, perhitungan V(G), dan daftar jalur independen untuk satu fungsi dengan minimal 3 keputusan
(2) Test PyTest yang menutup semua jalur tersebut
(3) State machine dan tabel transisi untuk satu class dengan minimal 3 state
(4) Test class yang mencakup transisi valid dan tidak valid, serta minimal 1 kasus pewarisan atau polimorfisme
(5) Laporan --cov-branch beserta analisisnya
